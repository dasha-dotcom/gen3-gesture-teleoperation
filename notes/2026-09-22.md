# September 22, 2026 — completed mock pick-and-place milestone

## Result and scope

The end-to-end path is complete: Mac webcam → MediaPipe palm position/apparent width/gesture → UDP → calibrated x/y/z MoveIt Servo control and Robotiq gesture commands → proximity-based planning-scene attachment → transport → detachment → target evaluation. The working code is recorded in `8ce054fbcb2cc7b7cd0b2068303ef247fa2a6d63` on `feature/pick-and-place`.

This is a simulation-first milestone on mock Gen3 + Robotiq 2F-85 hardware. **RViz/MoveIt attachment is logical simulated grasping, not contact physics or real-robot validation.** A detached cube remains at its released scene pose: there is no gravity, friction, force/torque feedback, or proof of a physically stable grasp/place.

## Five standardized trials

These are the user-recorded results from the interactive VM session, summarized on September 22; they were not rerun by the documentation update. An earlier practice run used a different start and is excluded. The five standardized trials began at Home with the gripper OPEN, the 5 cm cube reset to `(0.537, 0.004, 0.327)` m and the 14 × 14 cm target at `(0.50, -0.18, 0.20)` m in `base_link`.

*Trial 2: 74.90 s is the successful re-pick → final placement interval; first pickup → final success took 109.30 s. The mean below uses 74.90 s, not the full recovery sequence.

- **5/5** tasks ultimately completed; **4/5** first-placement successes; **1/5** recovery after a miss.
- Successful pickup → successful placement: mean **55.78 s**, median **45.30 s**.
- Final planar error: mean **2.55 cm**, median **2.20 cm**, best **0.60 cm**, worst successful **6.62 cm**.

This is a **small mock-hardware validation set**, not a rigorous performance evaluation. These intervals exclude the initial approach and unsuccessful grasp attempts before the successful pickup; first-placement success does not mean first-grasp success.

Timing is based on watcher pickup/place log events. Final planar error is the distance from released cube center to target center in x/y, computed from the reported offsets. Values are rounded summaries, not a claim of sub-millimeter measurement accuracy. Trial 4 succeeded near the square's edge; success uses per-axis ±7 cm bounds, not a radial 7 cm tolerance. The criterion ignores height and does not require the whole 5 cm cube to fit inside the target.

The normal between-trial reset was: open/detach → release Space → pause Servo → RViz Home → unpause Servo → remove/add cube → reapply gripper contact allowances → C → next trial. Detailed commands are in the [operation guide](../docs/mock-teleoperation.md).

## Debugging decisions preserved

- Kept camera processing on the Mac and ROS in Ubuntu. The current combined sender/bridge use port 5007 and session-aware packets; older y/z examples remain separately documented.
- Calibrated apparent palm width supplies an x proxy alongside y/z. It is affected by hand orientation; it is not metric camera depth. z is slower, and combined translation is normalized before the Servo scale.
- Used stabilized OPEN/CLOSED gestures for 0.0/0.4 rad gripper targets. Kept the pick/place watcher separate from the working teleoperation bridge.
- Allowed only the listed gripper/mount links to contact the cube in the planning scene. Kept Servo collision checking enabled for other robot links.
- Measured grasp proximity from the midpoint of the two fingertip links rather than the mounting `end_effector_link`. Used an 8 cm radius, rechecked while CLOSED. This deliberately permissive proximity test is not a contact test; initial closes around 11 cm away correctly did not attach in recorded runs.
- Queried fingertip TF in the cube's returned planning-scene frame, which can be `world`, instead of mixing frames.
- Read the current single-box object's actual returned center from `CollisionObject.pose`; primitive poses are relative to that object. This fixed the cube-position and placement checks captured in the working commit.
- Placed the blue target below working height to reduce collision interference. It remains a planning-scene collision object; evaluation uses only x/y because gravity/contact are absent.
- Used pause/unpause services around RViz Home moves to avoid concurrent Servo output and planned execution. The separate terminal Home helper attempted during the session did not work; RViz Home is the documented manual reset path. Automatic singularity recovery remains in the combined bridge.
- Twist mode is selected by bridge startup. Re-select it when troubleshooting an unset command type after restart, not as a mandatory step after each Home move.
- Excluded the nonstandard starting-position practice run and distinguished Trial 2's successful re-pick interval (74.90 s) from its full first-pickup recovery sequence (109.30 s).

## Important limitations and follow-up

- Five trials are a small mock-hardware validation set, not a rigorous performance study, general success-rate estimate, or human-subject comparison.
- Logical attachment does not validate contact, friction, grasp stability, placement support, or a real robot. There is no physics simulator in this task path.
- Translation only; zero angular commands do not actively restore orientation. Drift, network/GUI delay, and stopping latency remain unquantified.
- Space gates webcam arm/new gripper commands. It does not cancel an already-issued gripper action or the automatic planned Home trajectory. The watcher independently responds to gripper state without a Space gate.
- Automatic Home recovery can fail and leave Servo paused/input faulted. The earlier planned-motion action-cancellation limitation remains unresolved; mock stopping observations are not emergency-stop certification.
- The lab arm/gripper match is provisional. Upstream package/source revisions and a clean-machine installation are not verified/pinned.
- Existing dependency-free tests target the earlier y/z bridge; they do not exercise the current combined bridge, ROS recovery, or scene watcher. The evidence here comes from the recorded interactive session.

The documentation wrap-up changes no working control logic. The feature branch is to remain separate from `main` pending later review; no merge is part of this milestone cleanup.
